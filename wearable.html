Connected by design

A connected vision, rehearsed in software

The physical charm is a product vision. The current milestone is an authenticated, same-computer simulator that an iOS or Android development build connects to only after a developer chooses to do so. Its battery, connectivity, cue, readiness, and receipt values are synthetic process-memory records—not wearable telemetry.

Prototype 1.3 is an internal software-contract milestone, not an app release or product version. It rehearses a synthetic reboot marker (a simulated restart), a closed ownership-state fixture (a fixed set of test-only states), bounded replay summaries (a limited history of repeated requests and results), and explicit cancellation outcomes. These records are not physical identity, secure ownership, provisioning, or durable device storage.

From product vision to verified prototype

01 · Product vision

NorthStar is designed to pair with the mobile app; physical pairing and radio behavior are not implemented by this software simulator.

02 · Explicit rehearsal cue

After both local endpoints are connected, the developer presses one mobile control to request a synthetic check-in continuity cue.

03 · Local readiness

Readiness distinguishes a new request from a known retry. New work is allowed only in the simulator's predefined owner-bound test state. “Owner-bound” is only a software label; it does not prove who owns a device. These results describe only whether this local state machine can admit the cue—not hardware, wearer, safety, or production readiness.

04 · Evidence without assumed success

Identical retries reuse a limited history of prior results; conflicting reuse is rejected. A developer may cancel a still-pending synthetic request before it reaches its final processing boundary. Only a confirmed cancelled result counts as cancellation; too late, missing evidence, and unknown remain unresolved. Explicit lab expiry is a fallback for a stuck, unfinished fixture—not cancellation success. Synthetic reboot scenarios also remain unknown or unavailable, never assumed successful.

Simulation-only boundary

A continuity record is not a delivered check-in

The current endpoint is a deterministic localhost contract for engineering review.

The cue is recorded only after an explicit developer action in the mobile lab; no monitoring or automatic trigger runs.

Requested, acknowledged, accepted, executing, and executed are local process-memory receipt states; executed never means a person or device received anything.

After a local reset, the simulator keeps a limited record of previously used request keys until a developer explicitly creates a new simulator binding. This prevents an old request from silently becoming new work.

The production-gate review mode remains local simulation and blocks simulated continuity cues and vibration requests.

No physical wearable, vibration, message, location share, contact, emergency action, or external effect occurs. Full product specifications will be shared before launch.

Prototype and production path

Built for iOS and Android development

The same-computer rehearsal supports iOS Simulator loopback and the Android Emulator’s fixed host alias. NorthStar connectivity remains in development and is not part of the mobile beta. Production still needs physical firmware and radio integration, device identity and provisioning, secure transport, recovery, battery and failure testing, privacy controls, and release approval.
